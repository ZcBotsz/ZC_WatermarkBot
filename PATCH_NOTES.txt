ZC Watermark Bot — current Render package

This package contains the current production source and runtime assets. It includes the tested UI/PDF/font changes and a per-user channel-automation workflow (owner + Infinity plan).

User processing and settings:
- `/start` plays the supplied hard-coded bar loading animation: one message is edited through `▱▱▱▱▱▱▱▱ → ▰▰▰▰▰▰▰▰` frames (with a typing indicator), then hidden, and the start photo with greeting caption and menu buttons is sent as a fresh message, never a reply. There is intentionally no setting to change or disable the animation.
- Back navigation is available on settings/help/plans/usage/admin screens; Close actions are removed.
- Background Box has explicit ON and OFF controls.
- PDFs now have a fully independent watermark profile: separate text, font, size, colour, opacity, uppercase, outline, shadow, background box/border, pattern (static/tiled), position, margin and rotation. Old saved settings are migrated once (the video design is snapshotted into the PDF profile), then the two profiles never track each other. A PDF preview button renders the profile on a sample page, and PDF auto-contrast uses a true contrast check so light text cannot vanish on white pages.
- Font picker rescans bundled/user/system font directories; Docker checks for bundled `assets/fonts/Poppins-Bold.ttf`.
- Static video watermark coordinates align to even pixels to reduce chroma-alignment jitter. Use Static to avoid intentional motion. Actual playback still needs a sample-video check.
- Processing/progress cards now use the requested compact layout: filename, Tasks, Stage, a 12-cell progress bar with two-decimal percentage, then Processed, Size, Speed, ETA, Elapsed, Upload, Engine, and User in `Label : value` rows with no emoji on every row. FFmpeg shows its detected version when available.
- Video/PDF encoding uses one shared sequential watermark worker by default.
- Telegram downloads are now parallelised (the FastTelethon/tdl technique): files of 8 MB+ are split into 4 MiB ranged segments fetched concurrently over `TG_DOWNLOAD_CONNECTIONS` (default 4) connections — the main client plus extra no-updates bot sessions (`<SESSION_NAME>_dl1...`) that exist only to download — and written at their offsets with per-segment retry/resume. This lifts the ~2-3 MB/s single-connection ceiling; small files and any parallel failure fall back to the classic `download_media` path. Set `TG_DOWNLOAD_CONNECTIONS=1` to disable, or raise to 6-8 on fast servers (watch for FloodWaits).
- Uploads now rotate across the main client and those helper sessions, so concurrent uploads (`UPLOAD_SLOTS`) each ride their own connection. `ENCODE_SLOTS` now actually controls parallel watermarking workers (it was previously ignored by the pipeline): values above 1 watermark several files at once with FFmpeg threads divided between them, trading a little per-file speed for much better queue throughput.
- Fixed a feedback loop where the bot watermarked its own output: the finished file it sent arrived back as a message from the bot account and was processed again (2-3 ever-larger copies of one file). The media handler now ignores the bot's own/outgoing messages and never starts two jobs for the same delivered message.
- The configured `OWNER_ID` now always receives Infinity-tier limits automatically (2,000 MB per file, unlimited daily jobs, top priority) without needing a manual plan grant, so the owner can never be stopped by a Free 50 MB limit.
- Telegram's bot upload cap is 2,000 MiB (4 GB is only for Premium *user* accounts; bots cannot be Premium, and no local Bot API server or env change lifts this). Channel automation now checks the real source size BEFORE watermarking: a video/PDF post over 2,000 MiB is copied to the target channel unchanged (server-side copy, caption preserved, no "Forwarded from" tag) and the owner is notified — instead of wasting a long encode on a file that could never be uploaded. The same copy fallback applies if a watermarked output itself grows past 2,000 MiB, and personal jobs that exceed it fail with a clear explanation instead of an "Unexpected error".
- Captions longer than Telegram's 1,024-character media-caption limit no longer need manual handling: the first part stays on the video/PDF and the remainder is sent as follow-up message(s) replying to it.
- Settings can be backed up and restored: Settings → **📤 Export settings** sends a `zc-watermark-settings.json` file (video + PDF profiles together). To restore, simply send that file back to the bot — it is validated and applied automatically, with no manual re-entry. Unrelated or invalid .json files are rejected without changing settings.

Channel automation:
- **Channel Automation** is open to the owner and to Infinity-plan users (`/automation`, the `/start` menu, My Plan, and the owner's Admin Panel). Every user configures their own source/target channels (by forwarded channel post or `@username`/numeric ID), their own queue, watermark settings and plan file-size limits; queues and settings are fully isolated per user and existing owner configuration/queue data migrates automatically.
- Permission check requires the bot to be an administrator in the source and to have posting rights in the target.
- Every new source-channel post is queued while that user's automation is running. Only video/PDF posts are watermarked with that user's current settings; all other posts (text, photos, stickers, audio/voice, and non-PDF documents) are copied unchanged to the target without a Telegram "Forwarded from" tag.
- Automated watermarked files keep the source caption and base filename where possible, regardless of personal caption/name preferences. Video output selects the same MP4/MKV container where supported and falls back to a compatible MP4/MKV container for other inputs.
- Old posts are added by manually forwarding them while Backfill mode is active. Backfill holds processing while new channel posts are also queued, then releases the queue by oldest source-message ID. The bot-token session does not fetch full old channel history.
- Queue state and deduplication IDs are stored in SQLite. Pause finishes the current item and retains pending items; Retry failed and Skip failed controls are available. A confirmed **Stop & clear queue** action turns automation/backfill off, cancels the user's current automation watermark, and deletes queued/processing/failed items so an old backfill cannot resume; completed history is retained to prevent duplicate target posts, and cleared unfinished posts can be queued again. Cancelling an automation watermark card now pauses that user's queue instead of advancing to the next item.
- Source edits are ignored; NSFW screening is not included; media albums are handled per message.

Validation: `python -m compileall -q wmbot tests` succeeded; the full local test suite passed **130 tests**, including PDF-profile independence/migration, auto-contrast, per-user automation isolation/access, legacy-database migration, stop-and-clear queue semantics, cancel-pauses-queue behavior, parallel download assembly/retry/fallback/cancel, upload connection rotation, ENCODE_SLOTS processing workers, bot-never-reprocesses-its-own-output, duplicate-delivery dedupe, owner top-tier limits, oversize posts copied instead of watermarked (before encoding and after output growth), long captions split into a follow-up message, settings export/import round-trip, the compact progress card, and the /start bar-animation → photo sequence. Telegram calls were mocked; no live Telegram automation or Render deployment was performed, so real-world transfer throughput still needs a live test on the server.
